  Goal

  Create a new Android app in this repo that emulates the core, portable features of mixxx-desktop — 2-deck playback, mixer (gain/EQ/crossfade), tempo/sync, loops/hotcues, waveforms, track
  library, and a small effect set — as a touch-first Kotlin app. You do not need to create Android Studio boilerplate; I will scaffold it myself from the command line.

  Success Criteria

  • A new Gradle module (e.g. mixxx-android/) builds with ./gradlew assembleDebug and installs on an emulator/device.
  • User can: pick 2 audio files, play/cue/pause per deck, crossfade, adjust per-channel gain + 3-band EQ, change tempo, toggle sync, set a loop, trigger 2–3 hotcues, and apply one effect
    (filter/echo) per deck.
  • Waveform display scrolls during playback; library remembers tracks, cue points, and BPM.
  • No GPL violation: Mixxx is GPLv2; the new app either stays local-only or carries compatible licensing/attribution.

  Approach

  • Do not port mixxx-desktop C++/Qt. It is a desktop Qt/CMake codebase (mixxx-desktop/src/engine/, mixer/, effects/, library/, waveform/, controllers/) with a real-time engine thread and
    ControlObject messaging per mixxx-desktop/AGENTS.md. Direct reuse on Android is high-risk.
  • Build a clean-room MVP in Kotlin that mirrors Mixxx behavior described in the Mixxx 2.5 interface manual: Decks (§3.2), Mixer (§3.3), Effects (§3.5), Samplers/Preview (§3.4/§3.7),
    Library (ch. 4), DJ techniques like sync/looping (ch. 12).
  • Audio stack: Media3/ExoPlayer for MVP decoding + tempo/pitch, with architecture seam to swap in Oboe (AAudio, LowLatency + Exclusive, data-callback, no blocking per the low-latency
    checklist) for the DJ-critical mix path in a later phase. This keeps MVP shippable without NDK on day one.
  • UI: single-activity Jetpack Compose, landscape DJ layout: 2 deck cards + central mixer strip + bottom library sheet. No custom skins, vinyl DVS, controllers, broadcasting, or 4-deck
    mode in MVP.
  • Assumptions: Kotlin + Compose + Media3; minSdk 29, targetSdk 34; Room for library/cues; new top-level folder so mixxx-desktop/ stays untouched.

  Steps

  1. Scaffold mixxx-android/ myself. Gradle wrapper, settings.gradle, app module, JDK 17 note (your SDK exists at ~/Android/Sdk but java is currently missing — install Temurin 17 before
     go). Verify with assembleDebug.
  2. Domain model. DeckState, MixerState, TrackMeta, CuePoint, Loop — mirrors Mixxx deck/mixer semantics, no Android dependencies so it is unit-testable.
  3. Playback engine v1 (Media3). Two player instances, per-deck play/cue/pause, rate/tempo, Sonic-style time-stretch; software gain + 3-band EQ + crossfader mix in the output path.
  4. Deck UI. Transport, jog/seek, waveform view (precomputed peaks, not Mixxx GLSL shaders), BPM + sync (simple leader/follower, not Mixxx's full sync engine), loop in/out, 3 hotcues per
     deck.
  5. Mixer UI. Per-channel gain, hi/mid/low, PFL-less headphone/main faders, crossfader with linear curve.
  6. Effects v1. One insert slot per deck: filter + echo only (Mixxx has chainable racks — deferred). Wet/dry knob.
  7. Library. MediaStore picker + Room cache: title/artist/BPM, playlists/crates-lite, remembers cues/loops; AutoDJ/queue deferred.
  8. Polish + licenses. App icon, dark DJ theme, GPLv2-compatible LICENSE/NOTICE noting Mixxx inspiration, README with build/run steps.

  Validation Plan

  • ./gradlew :app:testDebugUnitTest — engine math (mix curves, tempo mapping, loop/hotcue state).
  • ./gradlew :app:assembleDebug + install on emulator via existing adb; manual script: load 2 tracks → play both → crossfade full L/R → EQ kill → sync → loop → hotcue → effect on/off,
    listening for glitches/dropouts.
  • Highest-risk check is simultaneous-deck audio stability (underruns, sync drift) — exercise on a real device, not just the emulator.

  Risks / Open Questions

  • Latency: Media3 cannot hit pro-DJ latency; if you need scratch-grade response, Phase 2 must move mixing to Oboe/AAudio native. Accepted for MVP.
  • Format/BPM gaps: MVP decodes what Media3 supports and uses simple BPM detect/tap; Mixxx's analyzers (KeyFinder, Chromaprint, Rubber Band) are out of scope.
  • Scope cuts vs. Mixxx: 4 decks, samplers, mic/aux, vinyl control, MIDI/HID controllers, live broadcasting, and skinning are explicit non-goals for MVP.
  • None blocking: after go I will pick mixxx-android/ as the path and 2-deck MVP unless you say otherwise.
