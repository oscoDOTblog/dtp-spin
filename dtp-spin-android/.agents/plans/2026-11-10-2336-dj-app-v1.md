## Goal

Build a Mixxx-inspired, touch-first two-deck DJ app for Android tablet (Kotlin + Jetpack Compose + C++/Oboe), optimized for personal DJ practice: fully offline, no external hardware required. First success criterion: import two local MP3s, load one per deck, play simultaneously, crossfade without glitches.

## Success Criteria

- User can import local MP3/WAV (FLAC/M4A where supported), see them persist after restart, load into Deck A/B.
- Two decks play simultaneously for 30+ min; loading one deck never interrupts the other.
- Manual transition possible: play/pause/cue/seek, channel volume + gain, 3-band EQ, manual tempo slider, equal-power crossfader.
- Waveforms scroll with playhead; library search works; session (loaded tracks + settings) restores.
- No disk I/O, allocation, blocking locks, or JNI inside the real-time audio callback.

## Approach

Keep UI and audio strictly separated: Compose/ViewModel/StateFlow on top, one native C++ engine (C++17 + Oboe) doing all mixing in a single stereo output callback, Kotlin decoding via MediaExtractor/MediaCodec feeding PCM to native on worker threads. Current repo is greenfield (`com.dtp.spin`, minSdk 30, no Compose/Room/NDK yet), so build the foundation in dependency order: Gradle deps → native engine PoC → SAF import → deck UI → DSP controls → stability.

Key dependency decision: local file import moves to P0 (right after audio PoC), not a later milestone — it is required to test anything real. Persist SAF URI permissions in Room; do not copy music into app storage.

## Steps

### Phase 0 — Project foundation

- Add to `gradle/libs.versions.toml` + `app/build.gradle.kts`: Compose BOM + Material 3, Room, DataStore, lifecycle-viewmodel-compose, Oboe (prefab), JUnit/Espresso already present.
- Enable landscape tablet layout, `MainActivity` Compose entry, `DJApplication`, manual DI (Hilt only if complexity grows).
- Add `externalNativeBuild` + CMake (`app/src/main/cpp/CMakeLists.txt`, target `arm64-v8a` + emulator ABI), `System.loadLibrary("djengine")`.
- Files: `AudioEngine.kt` (interface for fakes/previews), `NativeAudioEngine.kt`, `DeckState.kt`, `AudioEngineState.kt`.

### Phase 1 — Audio proof of concept (P0)

- Native classes: `AudioEngine` (owns Oboe stream + callback), `Deck` (position/transport/rate/cue), `TrackDecoder` (worker thread), `AudioRingBuffer`, `Resampler` (plain rate; pitch changes with speed — key lock deferred), `Mixer` (equal-power crossfade), `MasterProcessor` (limiter), `EngineCommandQueue` (atomics/lock-free, UI thread never blocks audio).
- `jni_bridge.cpp`: `load/play/pause/seek/volume/crossfade/EQ/rate` + ~20–30 Hz state publish via StateFlow.
- Validate with bundled WAV → test tone → decoded file → two decks + crossfader.

### Phase 2 — Local import + library (P0)

- SAF multi-file picker, persist URI permissions, duplicate detection by URI, file validation with user-visible errors.
- Metadata (title/artist/album/duration) via MediaExtractor/MediaMetadataRetriever; Room entities: tracks, cues; DataStore for settings/session.
- Searchable library UI with Load-to-A/B actions; graceful handling of moved/deleted files and revoked permissions.
- Decode path: SAF URI → MediaExtractor/MediaCodec → PCM buffers → native engine, always off the audio thread.

### Phase 3 — Touch-first DJ interface (P0)

- Landscape layout: decks top (BPM display, tempo slider, transport), mixer middle (gain/HIGH/MID/LOW, channel volume, crossfader -1.0..+1.0), collapsible library bottom.
- Components: `DJScreen`, `DJViewModel`, `DeckView`, `WaveformView` (Compose Canvas from cached peaks), `MixerView`, `EQKnob` (double-tap reset), `Crossfader`.
- Gestures: tap waveform = seek (when paused), drag = scrub, tap Play/Cue, long-press Cue = set cue, drag tempo/crossfader.

### Phase 4 — Mixing controls (P1)

- 3-band EQ (`ThreeBandEQ.cpp`) per deck, manual playback-rate slider, saved cue points, seek; waveform peak caching at import for smooth scroll.
- Defer: auto BPM detect/sync, beat loops + hot cues beyond basic cue, filter, recording, headphone pre-cue (keep engine cue-bus hook architecturally but no UI), scratching, 4 decks, FX, stems, streaming, MIDI, auto-DJ.

### Phase 5 — Stability and practice readiness (P1)

- Audio-focus handling, notification/interruption recovery, background/foreground lifecycle, screen-awake during mix, clipping protection, no-click gain smoothing.
- Device testing on real tablet early (latency varies; emulator is not representative); CPU/load profiling; 30-min soak test.

## Validation Plan

- `Import two MP3s → load A/B → play → crossfade`: no glitches, other deck uninterrupted.
- Kill + relaunch: library, cues, last session restore.
- Revoke/move a file: clear error, no crash.
- 30-min dual-deck soak on target tablet: no dropouts/crashes; EQ/volume/tempo moves artifact-free.
- Code-level: callback does no I/O/alloc/JNI (review + tracing); `./gradlew :app:assembleDebug`, `:app:test`, connected tablet run.

## Risks / Open Questions

- Risk: Oboe/NDK integration + device latency variance — mitigate by testing on the real tablet in Phase 1, not Phase 5.
- Risk: plain resampling shifts pitch with tempo — accepted for V1; key lock is a named follow-up.
- Risk: Mixxx DSP reuse tempting but desktop-oriented + GPL obligations — decision: clean Android-native engine, Mixxx as functional reference only, permissive-licensed DSP libs selectively.
- Non-goals V1: sync/beatgrid editing, scratching, recording, MIDI, streaming, stems, FX chains, 4 decks.
- Open: none — use case fixed as personal practice on tablet speakers/single output; multichannel USB cue routing deferred to live-performance follow-up.
